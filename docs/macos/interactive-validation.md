# 桌面交互验收

## macOS：完整浏览器登录仍待确认

验证基于 `623ba552ad69b7afa8ec59ff0193a4f88e56ec5e` 的 CI Release 产物。为了从零账号开始且不影响已有账号，复制应用并改用独立测试 Bundle ID，重新进行本地 ad-hoc 签名；Dart 与原生程序代码保持 CI 产物不变。这不是原始 ZIP 的逐字节复测。

已观察到：

- 独立配置账号记录为 0，从应用发起浏览器授权，用户确认完成授权并回到测试应用，但检查时仍停在登录页，账号记录仍为 0。完整登录未通过。
- 将 `pixiv://` 临时关联到测试应用后，普通作品链接能唤起并导航到详情，说明该进程的热启动 URL 接收和导航路径工作；这不能单独证明授权码交换成功。
- 新配置的 OAuth/API 默认使用强制 ECH，详情请求出现 `DioException [unknown]: null`。此前已正常工作的配置使用标准连接。ECH 是待验证的网络差异，尚未确认具体失败原因。
- 已在测试配置中将 OAuth/API 改为标准连接并重新发起授权；只有观察到账号从 0 变为 1、推荐页正常加载，以及重启保持登录，才能关闭此验收项。

后续复测需要重新从应用发起授权，不复用旧授权链接。检查系统协议处理器，测试结束后恢复原关联；仅记录账号数量及界面结果，不收集授权码、Token、数据库内容或完整回调 URL。
